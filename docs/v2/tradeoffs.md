# V2 architecture tradeoff register

This register makes every intentional compromise addressable from ADRs, design contracts, implementation reviews, and
evidence. `Accepted` freezes the direction; `Provisional` requires its named spike or gate before implementation freeze.

| ID | Status | Decision | Gain | Cost / risk | Mitigation and evidence gate |
| --- | --- | --- | --- | --- | --- |
| T-APPEND-01 | Accepted | Primary-WAL durability, not per-append metadata, linearizes append; combined tracker/locator reservation precedes position allocation and local locator/frontier publication precedes ACK | removes control-plane latency, lets B advance/read while A has a typed gap, and avoids capacity failure after allocation | provider-unknown lanes still block physical order; reservation/ring/index need hard bounds; active-tail publication adds local allocation/GC cost | ADRs 0038/0039/0063..0069, `V2-APP-001..003`, `V2-OBJ-002/008..011/020..024`, `V2-READ-003/004`; zero normal-append remote I/O |
| T-PROTOCOL-01 | Accepted | Kafka/Pulsar keep protocol-native complete commit units; after shared Object/header/directory validation, frame-local validation and binding frontier release are independent | protects Kafka commit-set/idempotency semantics, opaque Pulsar entries, random reads, and cross-binding isolation | per-frame descriptors/AEAD tags, layered shared/local failure handling, weaker cross-frame compression, and two checksum layers | ADRs 0026/0031/0040/0064, Kafka/Pulsar parity, `V2-OBJ-002/004/006/012/021` |
| T-POSITION-01 | Accepted | Pulsar Object WAL uses explicit chain authority plus one immutable fixed aligned `2^40`, never-reused Cell slice under exactly one fresh-root, canonical UUID/NLI1-derived compatibility-namespace Registry with two closed writer kinds, canonical 120-byte cohort rows, immutable admission evidence, and interlock; allocator selection requires native-relative evidence, and any RANGE grant survives owner-only takeover with same-RESERVED completion/one-candidate burn | preserves stock MessageId/chain semantics while avoiding Object-derived positions, omitted-writer collisions, second namespace identity, external writer-set authority, random writer-row identity, multi-slice recovery, unevidenced mode selection, and failover-wide range reacquisition | Registry/writer/ACL admission governance, qualified fresh-root proof, evidence-derived writer count, serialized assignment/grant administration, permanent tombstones/orphans, fixed-slice waste, native-generator fork, finite capacity, background-clear HOL, and mandatory scale evidence | ADRs 0022/0027/0032/0041/0048/0054/0055/0061/0081..0085, `V2-POSITION-001..018`; Registry and harness receipts are distinct; STRICT/RANGE remain open |
| T-MULTIPROTOCOL-01 | Accepted | independent Kafka/Pulsar Protocol Cells may share one Storage Fabric | one lifecycle platform without merging protocol authority | multi-protocol identity and operations remain explicit | `V2-MULTIPROTOCOL-001`; provider sharing follows `T-FABRIC-01` |

| T-MIGRATION-01 | Accepted | keep the append-only typed Storage Epoch model, but create exactly one initial epoch and ship no online transition in 0.2 | future-compatible durable shape without transition risk in the core rewrite | no online cost/performance switch for an existing Topic Incarnation | ADR 0015 and `V2-MIGRATION-001`; future transition requires new accepted gates |
| T-PROJECTION-01 | Accepted | retain Access Projection/Migration Link boundaries and dual-authority rejection, but ship no cross-protocol runtime in 0.2 | focuses acceptance on native Kafka and Pulsar paths | no secondary-protocol serving or authority migration in 0.2 | ADR 0016 and `V2-PROJECTION-001`; detailed map/semantic questions remain deferred |
| T-OBJECT-01 | Accepted | NWG1 uses permanent lanes, authenticated frames, one Root/pointer, physical-only checkpoint/Seal, local tickets, shared-verified locators, NONE-default bounded proof rows, conservative prefix recovery, generation-tagged read pins, bounded inline anchors, permanent batch tombstones, and ADR-0088's strict v1 wire/failure corpus | one data PUT/no group metadata commit, stable range reads, compact inventory, exact compatibility authority, and no unevidenced skip/deletion state | prefix recovery GETs, optional token rows/page cost, active-tail slot/anchor/proof/protection/tombstone memory, O(N) retirement reconciliation, publisher residue, mandatory crypto, LIST restrictions, seal delay, and four separately governed corpus/evidence classes | ADRs 0030/0037..0040/0046/0047/0053/0058..0060/0062..0080/0088; M3-I0 A/B/C/D gates; `V2-OBJ-001..024`, `V2-READ-003..015` remain unpromoted until executable evidence |
| T-BK-01 | Accepted | BookKeeper ACK never waits for Object; native Pulsar metadata owns a deterministic NPD1-data/NPO1-root pair with checked streaming envelope/derived rows and attempt-persisted policy, one composite handle, source-pure fallback, BK-pin drain, and persisted delete intent/fact | preserves performance-first ACK and native lifecycle with bounded verifiable blocks, no multi-GiB allocation, deterministic defaults, and restart-safe deletion | cold-copy lag, block decode, streaming/multipart complexity, extra handles/pins, another delete-state write, retained BK bytes, bounded revalidation I/O, and cross-provider TOCTOU | ADRs 0017/0020/0024/0029/0035/0036/0044/0045/0052/0056/0057 plus `V2-BK-001..013` |
| T-LEDGER-01 | Accepted | Kafka BookKeeper profiles use one logical ledger chain per partition, coarse run/generation roots, packed in-ledger RecordBatch range indexes, owner-local active-tail locators, bounded overlapping I/O, and contiguous ordered publication; pooled cold-partition ledgers are deferred | Kafka Offset stays protocol truth, Produce avoids per-append metadata, Fetch targets one entry, recovery scans a bounded tail, and rollover/retention/source switching use a clear sealed-run unit | NBKE2/index/footer and ordered-pipeline complexity; active ledger handles, locator memory, checkpoint tail, and BookKeeper metadata may not scale to high partition counts | ADR 0086, M2-K0, and `V2-BK-003/014..017`; K0 owns exact persisted wire/hard caps/module/provider/gate inputs, K9 owns operational defaults and 10k/100k receipts, and failure blocks the profile or requires a new pooling ADR |
| T-KAFKA-01 | Accepted | keep Allocated/Durable/LEO/HW/LSO distinct; fence coherent locator/protocol publication before visibility; keep native duplicate identity separate from storage digests; send compact follower descriptors and split Observed/Applied; cap adoption by native election; persist leader epoch per commit; use profile-neutral BK/NWKCP1 checkpoints; Fetch uses native isolation/aborted metadata, delayed wakeup, floor+coverage+successor, and semantic compaction | preserves Kafka idempotency, transactions, elections, ISR/minISR/acks, compaction seek and low-amplification reads without per-Produce/Fetch metadata or duplicate follower payload writes | speculative producer state, fenced publication, descriptor journal/catch-up, Observed/Applied lag, checkpoint-vector compatibility, waiter contention, active-tail memory, and bounded takeover complexity | ADR 0087, M2-K0, and `V2-KAF-DATA-001..022`; M2 owns primitives/BK carriage and evidence, M3 owns exact NWKCP1 bytes/Head/key caps, M6 owns native broker/replica/election/error/transaction integration, mixed scenario rows cannot promote early, and storage-native ISR requires a new ADR |
| T-META-01 | Accepted | a Java-17/JDK-only domain plus exact four-capability SPI isolate one minimal independent-semantics aggregate; Kafka owns API-key-32000 aggregate metadata with one last-wins input-only pseudo-config, touched-topic validation, remote-log admission interlock, and linear residue-free final-batch admission, while Pulsar uses a permanent selector CAS plus a capability-gated authoritative ownership witness, client-only dummy ready barrier, one store-wide local continuity epoch, and one stale-install-safe atomic ACTIVE fence | native lifecycle ownership, retry-stable exact equality, no backend dependency or duplicate derived wire/config/child authority in the shared domain, no published half-topic, no ordinary O(all topics) scan/per-access Oxia, no server continuity protocol, and no same-name/ownership ABA | an extra module/artifact boundary and golden surface; Kafka fork/image/config/sizer/tool changes; two physical encodings; deferred NTA1 policy/caps; Pulsar client adapter/source-lock work and permanent rows; conservative store-wide reconnect revalidation; gap-safe invalidation proof; no online Kafka format upgrade | `v2M1FoundationCheck` covers the partial dependency/API/golden/artifact boundary; ADRs 0019/0023/0028/0033/0034/0042/0043/0050/0051/0081..0085, `V2-META-001..007`, `V2-KAF-META-001..005` own the remaining gates |
| T-MANIFEST-01 | Accepted | one logical Binding snapshot may span disjoint sources; one minimal ABA-safe lease pins each unfinished read batch; one selector CAS fuses fallback removal, E closure, E+1 grant and a small inline anchor under dedicated STOPPED reserve; immutable candidate verification and batched prune terminalize E; each source releases against its own interval and completed batch metadata becomes a permanent same-key tombstone | ACKed tail stays readable with zero per-read allocation/metadata, no cross-key interval race, no extra same-owner rollover, no batch-wide proof-hole HOL, no owner x batch writes, and no unsafe deletion/absence authority | StoreLoad/seqlock/pool/quarantine complexity, O(K) selector copy, terminal create/prune, N release CAS/O(N) scan, permanent tombstone capacity, invalid proof/source quarantine, and low-frequency control writes | ADRs 0067/0069..0080, `V2-READ-001/003..015`; tombstone deletion remains evidence gate 15, while physical proof/capability encodings remain evidence gates 08/09 |
| T-HANDOFF-01 | Accepted | planned typed handoff remains a hint; immutable Root/Seal/pointer own WalRun lineage, while Object-WAL fallback deletion separately requires fused selector closure, bounded inline anchors/emergency STOPPED reserve, closed-verifier terminal evidence, per-source quiescence, and exact protection release | lower healthy failover latency without promoting hints, cross-key rereads, backend history, ordinary owner role names, metadata compaction, or tombstone absence to deletion truth | Root/Seal/pointer/selector/anchor/terminal/proof/source-release control work, conservative source retention, permanent batch tombstones, and stale residue | ADRs 0039/0047/0063/0071/0073..0080; bounded WAL recovery plus durable quiescence/protection evidence |
| T-COMPAT-01 | Accepted | V2 is a clean break; Kafka level 2 is fresh-format only and V1/runtime feature transitions are rejected | avoids dual-read/write and state reinterpretation before customers exist | no in-place upgrade or downgrade | ADR 0034; distinct format identities, bootstrap gates, and explicit V1-state rejection |
| T-BENCH-01 | Accepted | performance claims use profile-specific, exact-source comparisons | makes “stronger” falsifiable | more expensive release evidence | pinned source tuple, same resources/request budget, receipt-backed thresholds |
| T-KOP-01 | Accepted | KoP remains designed but is outside the 0.2 runtime and release gate | keeps future compatibility thinking without distracting the core rewrite | KoP design may drift while deferred | retain the document; re-audit before activation |

No V2 implementation may close a `Provisional` row by changing prose alone. The spike result, selected decision, and
receipt must land in the same milestone change.
