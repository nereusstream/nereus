# ADR 0016: V2 0.2 cross-protocol runtime scope

## Status

Accepted for the 0.2 release scope. This ADR refines ADR 0013; implementation and runtime evidence are not started at
M0.

## Context

ADR 0013 separates secondary protocol access (`AccessProjection`) from native authority transfer (`MigrationLink`) and
forbids two Native Write Authorities. A usable Kafka/Pulsar projection or migration runtime would also need a durable
Projection Map, bounded seek/repair, cursor/group translation, batch and partial-ACK semantics, transaction and
visibility mapping, compaction, delayed delivery, schemas/properties/headers, deduplication, and crash-safe authority
transfer.

Those semantics are independent of proving the native Kafka and native Pulsar paths and would compete with the core 0.2
acceptance goals.

## Decision

0.2 retains the `AccessProjection` and `MigrationLink` domain boundary and validates that one Topic Incarnation cannot
obtain a second Native Write Authority. It does not implement:

- `ProjectionMapStore` or another durable projection-map service;
- secondary-protocol serving of a native topic;
- Kafka/Pulsar offset-position or semantic-state translation;
- cross-protocol backfill, catch-up, fencing, activation, rollback, or authority-transfer runtime.

The M1 model may represent projection and migration identities sufficiently to reject invalid dual-authority topology.
Those types are not a public feature promise and must not create a remote metadata dependency on normal append.

KoP remains designed and retained, but outside the 0.2 runtime and release gates. ADR 0016 neither deletes nor activates
the KoP design.

## Consequences

- `V2-OPEN-PROJECTION-SCOPE-01` is resolved for 0.2.
- `V2-PROJECTION-001` verifies model validation, absence of a second Native Write Authority, and absence of a production
  projection/migration capability; it does not claim cross-protocol serving.
- Projection-map granularity, semantic translation, and authority-transfer failure handling remain deferred questions
  and do not block the 0.2 release.
- The 0.2 engineering and acceptance budget stays focused on Kafka versus AutoMQ and Pulsar versus native Pulsar.

This decision is tracked by `T-PROJECTION-01`, `V2-PROJECTION-001`, and the deferred questions in
[V2 open questions](../v2/open-questions.md).
